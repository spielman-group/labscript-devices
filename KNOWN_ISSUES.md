# Known issues

- `PhaseMatrixQuickSyn/blacs_workers.py`: the worker's `update_reference_out`, `update_blanking` and `update_lock_recovery` do nothing, and `transition_to_buffered` writes `OUTP:STAT 1` without the `\r` every other command ends with and ignores the shot's gate.
- `FlyCapture2Camera/blacs_workers.py`: `_send_format7_config` skips Format7 settings that fail validation without saying so.
- `PulseBlaster/labscript_devices.py`, `PulseBlaster_No_DDS/labscript_devices.py`: each delay reaches SpinAPI as float nanoseconds (`delaydouble`), about 9% of them ~1e-12 cycles below a whole core cycle. Linux's `libspinapi64.so` (spinapi 3.2.2) rounds `length * clock - 3` to the nearest cycle in `pb_inst_pbonly64` and `pb_inst_dds2`, so loses nothing; the labs' Windows `spinapi64.dll` is a separate binary, unchecked. If it truncates, every repetition of such a looped step runs one cycle short (about 39 µs over a 2,905-step ramp). Needed: the same disassembly of that DLL, or a long looped ramp timed on a board.
- `AlazarTechBoard/blacs_workers.py`: `find_nearest_internal_clock` makes a 0-d array of the `dict_keys` it is given, so `transition_to_buffered` with the default `INTERNAL_CLOCK` raises TypeError (as upstream).
- `RFBlaster/blacs_workers.py`: the board has no status readback, so `shot_finished` is the default True, and the transition to manual does not wait for a secondary RFBlaster to end. Deferred: it needs the board's protocol.
- `NovaTechDDS9M/blacs_workers.py`: `check_remote_values` catches `socket.timeout`, which pyserial never raises; a NovaTech that does not answer gives empty lines, and the unpacking raises ValueError, not the "Cannot connect to device" error meant for it.
- `PrawnDO/blacs_workers.py`: smart programming of a program longer than the cached one, by at most 10%, writes past the end of the cached array in `transition_to_buffered` and raises IndexError.
- `PrawnDO/blacs_workers.py`: `transition_to_buffered` reports the final values from the stop row's ignored bit set, so BLACS shows every output low after a shot.
- `PrawnDO/labscript_devices.py`: for a clock other than 100 MHz, `__init__` scales `clock_limit` by `factor` as it does the times, but a rate scales by its inverse; PrawnBlaster had the same fault.
- `PrawnDO/labscript_devices.py`: `generate_code` gives a wait the bit set of the tick it resumes on, so an output change at the wait's own time shows during the wait, not after the retrigger; upstream's comment meant the wait to hold the previous state.
- `PulseBlaster/labscript_devices.py`: `get_direct_outputs` checks a connection's prefix and number but not that it suits the output's class, so a DigitalOut on 'dds 1' drives flag 1, one on 'dds -1' drives the last flag, and a DDS on 'flag 0' is taken as dds 0, while on 'flag 5' it raises a bare KeyError.
- `PulseBlasterESRPro200/labscript_devices.py`, `PulseBlaster_SP2_24_100_32k/labscript_devices.py`: `clock_resolution` is one core clock cycle, where the other boards' is two, so a symmetric tick of an odd number of cycles asks SpinAPI for half-cycle high and low times. Unchecked whether a board rounds both up and so lengthens the tick.
- `PineBlaster/blacs_tabs.py`: `get_child_from_connection_table` returns `'-'` for a port it does not find, and BLACS then raises AttributeError reading its `.name`; no port but 'internal' is asked for now.
- `DummyIntermediateDevice/labscript_devices.py`: a DummyIntermediateDevice with no outputs fails to compile; `generate_code` writes an OUTPUTS table of no columns, and h5py raises ValueError.
- `CiceroOpalKellyXEM3001/blacs_tabs.py`: `get_child_from_connection_table` searches the board's first child, which by name order is the wait monitor's pseudoclock, so it never finds 'Clock Out'; harmless while the tab creates no outputs.
- `CiceroOpalKellyXEM3001/labscript_devices.py`: `generate_code` merges instructions of equal periods with no cap, and the worker packs reps into 4 bytes, so 2**32 or more ticks at one period are silently cut short; it also merges a clock instruction into a wait whose timeout makes the same periods (3 or 4 ticks).
- `LightCrafterDMD/blacs_workers.py`: `transition_to_buffered` keys the final image "None", not the ImageSet's connection, so after a shot BLACS leaves the front panel on its earlier image while the DMD shows the shot's last one.
- `LightCrafterDMD/blacs_workers.py`: `_receive` reads the header and the body with one `recv` each, so a reply split across TCP segments is misread.
- `TriggerableCamera/labscript_devices.py`: `__init__` formats its message for a bad `saved_attribute_visibility_level` with a 4-tuple into one `%s`, so it raises TypeError, not the ValueError meant.
- `TriggerableCamera/blacs_workers.py`: `transition_to_buffered` pauses continuous acquisition, but `transition_to_manual` returns early for a shot with no exposures for the camera, so the acquisition is never resumed while the tab still shows it running.
- `TriggerableCamera/attributes_dialog.ui`, `blacs_tab.ui`: the text says IMAQdx, and tells every camera's users to pass the attributes as `imaqdx_attributes` to IMAQdxCamera; the keyword is `camera_attributes`.
- `FlyCapture2Camera/blacs_workers.py`: `set_image_mode` rounds the width and height to the offset step sizes, not the image step sizes PyCapture2 also reports; unchecked against a camera.
- `FlyCapture2Camera/blacs_workers.py`: `is_transient_grab_error` retries every Fc2error, so a fault that raises at once has `grab_multiple` retry it without pause until the shot ends.
- `docs/source/devices/pylon.rst`: gives the usage as `python ExposureTiming.py [camera_sn]`, which the script's argparse refuses; it takes `-sn SERIAL`.
- `PylonCamera/testing/ExposureTiming.py`: the last print labels `min_time_between_triggers` end-to-start, but when the exposure is at least the readout time it is start-to-start.
