# Known issues

- `PhaseMatrixQuickSyn/blacs_workers.py`: the worker's `update_reference_out`, `update_blanking` and `update_lock_recovery` do nothing, and `transition_to_buffered` writes `OUTP:STAT 1` without the `\r` every other command ends with and ignores the shot's gate, so `QuickSynDDS.disable()` has no effect.
- `FlyCapture2Camera/blacs_workers.py`: `_send_format7_config` skips Format7 settings that fail validation without saying so.
- `PulseBlaster/labscript_devices.py`, `PulseBlaster_No_DDS/labscript_devices.py`: each delay reaches SpinAPI as float nanoseconds (`delaydouble`), about 9% of them ~1e-12 cycles below a whole core cycle. Linux's `libspinapi64.so` (spinapi 3.2.2) rounds `length * clock - 3` to the nearest cycle in `pb_inst_pbonly64` and `pb_inst_dds2`, so loses nothing; the labs' Windows `spinapi64.dll` is a separate binary, unchecked. If it truncates, every repetition of such a looped step runs one cycle short (about 39 µs over a 2,905-step ramp). Needed: the same disassembly of that DLL, or a long looped ramp timed on a board.
- `RFBlaster/blacs_workers.py`: the board has no status readback, so `shot_finished` is the default True, and the transition to manual does not wait for a secondary RFBlaster to end. Deferred: it needs the board's protocol.
- `PulseBlasterESRPro200/labscript_devices.py`, `PulseBlaster_SP2_24_100_32k/labscript_devices.py`: `clock_resolution` is one core clock cycle, where the other boards' is two, so a symmetric tick of an odd number of cycles asks SpinAPI for half-cycle high and low times. Unchecked whether a board rounds both up and so lengthens the tick.
- `PineBlaster/blacs_tabs.py`: `get_child_from_connection_table` returns `'-'` for a port it does not find, and BLACS then raises AttributeError reading its `.name`; no port but 'internal' is asked for now.
- `CiceroOpalKellyXEM3001/blacs_tabs.py`: `get_child_from_connection_table` searches the board's first child, which by name order is the wait monitor's pseudoclock, so it never finds 'Clock Out'; harmless while the tab creates no outputs.
- `CiceroOpalKellyXEM3001/labscript_devices.py`: `generate_code` merges instructions of equal periods with no cap, and the worker packs reps into 4 bytes, so 2**32 or more ticks at one period are silently cut short; it also merges a clock instruction into a wait whose timeout makes the same periods (3 or 4 ticks).
- `FlyCapture2Camera/blacs_workers.py`: `set_image_mode` rounds the width and height to the offset step sizes, not the image step sizes PyCapture2 also reports; unchecked against a camera.
- `FlyCapture2Camera/blacs_workers.py`: `is_transient_grab_error` retries every Fc2error, so a fault that raises at once has `grab_multiple` retry it without pause until the shot ends.
- `SpinnakerCamera/blacs_workers.py`: `_decode_image_data` reads every Mono format not ending in 8 as uint16, but `GetData` returns a packed format such as Mono12Packed packed, 1.5 bytes a pixel, so the reshape raises a bare ValueError; Spinnaker unpacks only through `ImageProcessor.Convert`.
- `SpinnakerCamera/blacs_workers.py`, `FlyCapture2Camera/blacs_workers.py`: Spinnaker's `get_attribute_names` and FlyCapture2's `get_attributes_as_dict` ignore the visibility level, so `saved_attribute_visibility_level` saves every readable attribute.
- `AlazarTechBoard/blacs_workers.py`: the DMA buffers are freed only by a successful `transition_to_manual`; after an abort, a trigger timeout or a failure the next shot overwrites `self.buffers` and the memory leaks.
- `NI_DAQmx/blacs_workers.py`: `stop_task` stops and clears the acquisition task holding `tasklock`, which a late every-N-samples callback waits on; if DAQmx waits for that callback to return before `StopTask` or `ClearTask` returns, the two deadlock. NI's documentation does not say whether it does; upstream has the same structure.
- `NI_DAQmx/blacs_workers.py`: a wait monitor thread that will not stop is not a daemon, so at shutdown it holds the worker's exit until BLACS's kill deadline; restarting the tab is the remedy.
- `FunctionRunner/blacs_workers.py`: the functions are deserialised with `__name__` and `__file__` set to the device name, for `lyse.Run` to name its results group after the device, but lyse takes the group from `sys.modules['__main__'].__file__`, so the group is named after the worker's main script.
- runviewer draws nothing below a device that has no runviewer parser, such as a secondary pseudoclock triggered from a DummyIntermediateDevice: loading that device raises, and runviewer skips its children.
